## Architecture

**CRM-AC** is a Laravel 12 modular ERP. Access is gated per-user via a `services` pivot table (`user_service`). The two live modules are `inventory` (key: `inventory`) and `finance` (key: `finance`). `User::hasService($key)` handles permission checks; admins bypass all module gates. The `service:key` middleware enforces this on both web and API routes.

### Frontend pattern

Every module is a single Blade view (`resources/views/modules/`) that ships its own vanilla-JS logic imported via `resources/js/` (e.g. `finance.js`). There is no SPA framework — all state is managed with DOM manipulation and `fetch()` against the JSON API. Charts use Chart.js. The UI uses Tailwind + dark mode toggled via `localStorage('theme')`.

### API

All API routes live under `/api` with `auth:sanctum` + `throttle:60,1`. Module routes are further wrapped in `service:<key>` middleware. No versioning prefix. Finance routes live under `/api/finance/`, inventory under `/api/inventory/`.

### Module: Inventory

- Products, categories, stock tracking, CSV import (5,000 rows max, upsert on SKU)
- Multi-warehouse (`almacenes`) with locations (`ubicaciones`) and inter-warehouse transfers
- Lot/serial tracking (`lotes`) with FEFO ordering and expiry alerts
- Physical inventory counts (`inventario_fisico`) — create → count items → apply adjustments
- Stock alerts (auto-generated by `VerificarStockCommand`, resolable via API)
- AI stats via `OllamaService` (local llama3.2:3b) at `/api/inventory/stats/report`

### Module: Finance

- Transactions (income/expense) linked to accounts and categories
- Accounts with balance tracking and inter-account transfers
- Purchase orders (`compras`) with line items → receive flow updates inventory stock
- Accounts receivable (`cxc`) and payable (`cxp`) with payment recording
- Suppliers catalog
- Purchase and sale returns (`devoluciones_compra`, `devoluciones_venta`)
- Bank reconciliation (`conciliaciones`) — create → mark items → close
- Fixed assets with depreciation (`CalcularDepreciacionCommand`)
- Accounting periods with open/close/reopen cycle
- Reports: P&G, cash flow, aging CxC/CxP, DIOT
- AI advisor (4 modes: informe, forecast, anomalias, compras) via `FinanceAIService` → Ollama

### Key models

| Concern | Model(s) |
|---|---|
| Access control | `User`, `Service` (pivot: `user_service`) |
| Inventory | `Product`, `Category`, `InventoryMovement`, `Inventory\Almacen`, `Inventory\Lote`, `Inventory\InventarioFisico` |
| Finance | `Finance\Transaccion`, `Finance\Cuenta`, `Finance\Compra`, `Finance\CuentaPorCobrar`, `Finance\CuentaPorPagar`, `Finance\ActivoFijo`, `Finance\AsientoContable` |

### Artisan commands

- `php artisan stock:verificar` — generates stock alerts
- `php artisan vencimientos:alertar` — alerts on expiring lots
- `php artisan depreciation:calculate` — runs fixed asset depreciation

### Database

MySQL, DB name `CRMTEST`. Migrations live in `database/migrations/`.

### AI integration

`OllamaService` and `FinanceAIService` call a local Ollama instance (model `llama3.2:3b`). No external AI API calls. Rate-limited to 20 req/min on AI endpoints.
