## Commands

```bash
# First-time setup
composer run setup

# Dev (runs server, queue, logs, and Vite in parallel)
composer run dev
# Individually:
php artisan serve
npm run dev

# Build assets for production
npm run build

# Tests
composer run test           # clears config cache, then runs php artisan test
php artisan test --filter=TestName

# Code style (Laravel Pint, default preset — no pint.json)
./vendor/bin/pint
```

> **Gotcha:** after editing anything in `resources/js/`, run `npm run build` (or keep `npm run dev`
> running). A stale `public/build/` serves the old bundle and changes won't appear in the browser.

## Architecture

**CRM-AC** is a Laravel 12 modular ERP. Access is gated per-user by two pivots: `user_service`
(which modules a user has) and `almacen_user` (which warehouses a user can access). The live modules
are **`inventory`**, **`pos`**, and **`admin`** (plus auth). `User::hasService($key)` handles module
checks — admins bypass all gates and `expires_at` is honored. The `service:<key>` middleware
(`CheckServiceAccess`) enforces this on both web and API routes; `admin` and `password.change` are
separate middleware aliases (registered in `bootstrap/app.php`).

> **Finance was removed.** The `2026_07_30` migrations dropped the entire finance/accounting module,
> lotes/FEFO, and inventario físico (see "Removed modules" below). Their `create` migration files
> still physically exist but are dropped later, so a fresh `migrate` ends without those tables. Do
> not resurrect finance/lotes/inventario_fisico concepts — no controllers, models, or routes remain.

### Frontend pattern

Each module is a single Blade view in `resources/views/modules/` that ships its own JS entry from
`resources/js/`. There is no SPA framework.

- **Vanilla JS** (`inventory.js`, `admin.js`): guard on a root element id, a central `state` object,
  cached DOM refs, `api.get/post/...` fetches, and `innerHTML` renders via an `esc()` escaper.
- **Alpine.js** (`pos.js` only): exposes `window.posApp(defaultAlmacenId)`; Alpine loaded via CDN in
  the blade. `modules/pos.blade.php` is a standalone full HTML document (own `<head>`), not
  `@extends('layouts.app')`.
- **HTTP helper:** `resources/js/api.js` wraps the axios instance from `resources/js/bootstrap.js`
  (CSRF from `<meta>`, `withCredentials`; response interceptors: 401→/login, 419→reload, 403/429→log).
  Interface: `api.get(url, params={})`, `api.post/put/patch`, `api.delete(url, data={})`. Callers
  destructure `{ data }` and read errors from `err.response.data.{message,errors}`.
- **Shared UI is copy-pasted per module** (not shared): toast/notify, confirm dialog. A new module
  reimplements them.
- **Almacén selector pattern:** global `#almacen-selector`; inventory.js persists the choice in
  `localStorage['inventory_almacen']`, resolves the active almacén (stored id → `es_principal` → first)
  in `fetchAlmacenes()`, and appends `?almacen_id=` to every subsequent fetch. POS gets its default
  almacén server-side from the blade.
- Charts use Chart.js. Tailwind v4 (configured in `resources/css/app.css`, no `tailwind.config.js`),
  class-based dark mode toggled via `localStorage('theme')`. Vite entry points live in `vite.config.js`.

### API

All API routes live under `/api` with `auth:sanctum` + `throttle:60,1` (Sanctum SPA/stateful mode).
No versioning prefix. Module groups: `/api/inventory/` (`service:inventory`), `/api/pos/`
(`service:pos`), `/api/admin/` (`admin` middleware). Routes in `routes/api.php`; web module views in
`routes/web.php` under the `password.change` group.

### Module: Inventory

- Products, per-warehouse stock, CSV import → `Api\Inventory\{ProductController, ImportController}`.
- **Multi-warehouse** (`almacenes`) with locations (`ubicaciones`), shared across users via
  `almacen_user`, and **inter-warehouse transfers** (`TransferenciaController`: create/send/receive/
  preview; `transferencias_almacen` + `transferencia_items`).
- **Categories are per-warehouse.** A product's category is stored on `product_stock.category_id`
  (NULL = "general"), **not** on `products` (`products.category_id` was dropped by
  `2026_08_07_000001_categorias_por_almacen`). `CategoryController` scopes by `almacen_id` and counts
  members via `withCount('stocks')`.
- Stock movements (`MovementController`, `inventory_movements`: in/out/adjustment).
- Stock alerts (`alertas_stock`) auto-generated by `inventory:verificar-stock` (hourly cron via
  `VerificarStockService`), resolvable via API.
- Stats + AI chatbot via `GroqService` at `POST /api/inventory/ai/chat`
  (`Api\Inventory\StatsController`). Snapshot scoped to the user's accessible almacenes.

### Module: POS

- Point of sale → `App\Http\Controllers\PosController` (top-level, not under `Api/`).
- Product search, sales (`ventas`), sales stats. Models `Venta` / `VentaItem` (top-level).
- Payment methods `metodo_pago`: efectivo / tarjeta / transferencia. Sales are per-warehouse
  (`ventas.almacen_id`). `VentasDemoSeeder` seeds demo sales.
- View `modules/pos.blade.php` (standalone HTML document with Alpine). Depends on `inventory`
  (enforced in `AccessManager`).

### Module: Admin

- `admin` middleware. Controllers under `Api\Admin\`:
  - `UserController` — users CRUD, soft-delete restore, toggle-active, reset-password.
  - `UserAccessController` — reads/syncs a user's access (delegates to `Services\Admin\AccessManager`).
  - `ServiceController` — service catalog CRUD; `StatsController` — dashboard metrics;
    `AuditLogController` — audit trail (`audit_logs`); `ExportController` — CSV export of users.
- `AccessManager` atomically syncs services + warehouses, enforces `DEPENDENCIES = ['pos' => 'inventory']`,
  and writes an audit log.

### Removed modules (historical)

Dropped by the `2026_07_30` migrations, no code remains: **finance/accounting** (transacciones,
compras, proveedores, cuentas, cxc/cxp, devoluciones, conciliaciones, asientos_contables,
activos_fijos, periodos_contables, etc.), **lotes/FEFO** (`lotes`, `movement_lote`), and **inventario
físico** (`inventario_fisico`, `inventario_fisico_items`). Serial tracking survives only as
`products.requiere_serie` + movement notes.

### Artisan commands

- `php artisan inventory:verificar-stock {--almacen=}` — generates/resolves stock alerts (delegates
  to `Services\Inventory\VerificarStockService`). **Scheduled hourly** in `routes/console.php`.

### Database

App runs on **MySQL**, DB name `CRMTEST` (see `.env`; the framework default is sqlite). Migrations
live in `database/migrations/`. **Tests run on sqlite `:memory:`** (`phpunit.xml`), using
`RefreshDatabase`. Only `UserFactory` exists — other records are built with `::create()` in tests.

### AI integration

`GroqService` calls the Groq API (OpenAI-compatible `/chat/completions`, model configurable via
`GROQ_MODEL`, default `llama-3.1-8b-instant`). Requires `GROQ_API_KEY` (config in `config/services.php`
`groq` block: `GROQ_URL`, `GROQ_API_KEY`, `GROQ_MODEL`, `GROQ_TIMEOUT`). The inventory snapshot sent as
context is scoped to the requesting user's accessible almacenes. Rate-limited to 20 req/min on AI endpoints.
